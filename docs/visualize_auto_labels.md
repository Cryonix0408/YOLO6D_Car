# Visualize Auto Labels

This tool checks and visualizes labels generated by `scripts/generate_mocap_labels.py`.
It does not modify labels or images.

## Purpose

Use `scripts/visualize_auto_labels.py` before dataset building or training to confirm that:

- 12 car keypoints are projected onto the correct image locations.
- Keypoint IDs are ordered as expected.
- The 2D bounding box is reasonable.
- Label files and image files match one-to-one.
- Optional projected 3D bbox edges can be drawn when `annotations.jsonl` provides projected points.

## Expected Inputs

Typical auto-label output:

```text
G:\YOLO6D_Car_Data\outputs\auto_labels\<session_id>\
├── labels_yolo_pose\
│   ├── sample_000001.txt
│   └── ...
├── annotations.jsonl
├── summary.json
└── images.txt
```

Typical capture image folder:

```text
G:\YOLO6D_Car_Data\captures\<date>\<session_id>\images\
```

The YOLO pose txt format is expected to be:

```text
class_id cx cy w h kp1_x kp1_y kp1_v ... kp12_x kp12_y kp12_v
```

All bbox and keypoint coordinates in txt files are normalized. The script converts them to pixels for display.

## Validate Config

This mode resolves paths and imports OpenCV, but does not scan images or write output:

```powershell
D:\Envs\yolo6d\python.exe scripts\visualize_auto_labels.py `
  --labels-root outputs\auto_labels\2026-05-30_car_static_001 `
  --images-root captures\2026-05-30\2026-05-30_car_static_001\images `
  --paths-config configs\paths_local.yaml `
  --output-dir results\label_visualization\2026-05-30_car_static_001 `
  --max-samples 100 `
  --validate-config
```

## Run Visualization

```powershell
D:\Envs\yolo6d\python.exe scripts\visualize_auto_labels.py `
  --labels-root outputs\auto_labels\2026-05-30_car_static_001 `
  --images-root captures\2026-05-30\2026-05-30_car_static_001\images `
  --paths-config configs\paths_local.yaml `
  --output-dir results\label_visualization\2026-05-30_car_static_001 `
  --max-samples 100
```

With `configs\paths_local.yaml`, relative `outputs`, `captures`, and `results` paths resolve under `G:\YOLO6D_Car_Data`.

## Outputs

```text
G:\YOLO6D_Car_Data\results\label_visualization\<session_id>\
├── overlays\
│   ├── sample_000001_overlay.png
│   └── ...
├── contact_sheet.png
├── label_visualization_report.md
└── label_stats.json
```

## Checks

The report summarizes:

- label count
- image count
- matched label/image pairs
- missing images for labels
- images without labels
- invalid label files
- NaN or Inf keypoints
- visible keypoints outside image bounds
- invalid 2D bounding boxes
- visible keypoint count statistics

The final result is:

- `PASS`: sampled labels look structurally valid.
- `WARNING`: visualization ran, but some files need inspection.
- `FAIL`: no matched pairs were found or all matched labels are invalid.

## Optional 3D and Axis Overlays

If `annotations.jsonl` contains `projected_keypoints_px`, the script draws cuboid-style edges using the first 8 projected points.

Camera axes are drawn only when a record contains pre-projected `axis_points_px`. A GT pose matrix alone is not enough for this script to safely reproject axes unless camera intrinsics are also provided.

## Common Issues

- No matched pairs: image filenames and label filenames do not share the same stem.
- Keypoints outside image: check camera intrinsics, mocap rigid body names, and timestamp alignment.
- Bbox invalid: check object keypoint projection and label normalization.
- 3D edges not drawn: `annotations.jsonl` may be missing projected keypoints.
- Output goes to G drive: this is expected when using `--paths-config` with relative `results\...`.
